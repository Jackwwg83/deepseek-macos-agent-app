# DeepSeek Agent for macOS

DeepSeek Agent is a local-first macOS desktop app for running DeepSeek-TUI through a native shell and embedded chat UI.

It bundles the web UI and a `deepseek-tui` sidecar. Test users do not need to install Rust, Node, Xcode, or DeepSeek-TUI separately.

## Download

Latest tester alpha:

[DeepSeek Agent v0.1.0-alpha.4](https://github.com/Jackwwg83/deepseek-macos-agent-app/releases/tag/v0.1.0-alpha.4)

Download:

- optional checksum: `DeepSeek-Agent-alpha-macos.zip.sha256`

## Install

Requirements:

- macOS 13 or newer
- network access to the DeepSeek-compatible endpoint you configure

Steps:

1. Download `DeepSeek-Agent-alpha-macos.zip` from the release page.
2. Unzip it.
3. Open `DeepSeek Agent.app`.
4. In the left settings panel, enter your DeepSeek-compatible URL.
5. Enter your API key.
6. Choose or type the model name.
7. Click `Start DeepSeek`.

The API key is stored in macOS Keychain. The app starts the bundled sidecar on `127.0.0.1` with a fresh bearer token for each launch.

## Gatekeeper

This alpha build is ad-hoc signed but not notarized. If macOS blocks the first launch, right-click `DeepSeek Agent.app` and choose `Open`.

For controlled local testing, you can also clear quarantine:

```bash
xattr -dr com.apple.quarantine "DeepSeek Agent.app"
```

## Configuration

Users only need three values:

| Field | Example |
|---|---|
| DeepSeek URL | `https://api.deepseek.com/beta`, `https://your-host/v1`, or `http://your-self-hosted-server:port/v1` |
| API key | Stored in macOS Keychain |
| Model | `deepseek-v4-flash` |

The bundled sidecar is used by default.

`https://` is recommended for any public network. `http://` is allowed for self-hosted or private-network endpoints, but the app will show a warning because the API key is sent without transport encryption.

## What Is Included

- SwiftPM/AppKit macOS app shell
- Native settings sidebar
- API-key storage through macOS Keychain
- WKWebView chat surface
- React/TypeScript embedded UI
- Fake runtime for offline UI testing
- Real DeepSeek-TUI HTTP/SSE runtime adapter
- Bundled `deepseek-tui` sidecar in the tester package
- Package verification scripts and checksums

## Security Model

- Sidecar binds to `127.0.0.1` only.
- Runtime bearer token is generated by Swift per launch.
- API key is passed to the sidecar through environment, not command-line arguments.
- API key is not committed and is not written into package files.
- WebView production code does not store the sidecar bearer token.
- Package verification scans for API-key-looking secrets before release.

## Developer Setup

Install/check local prerequisites:

```bash
bash scripts/dev/bootstrap.sh
```

Run the full validation suite:

```bash
bash scripts/dev/check.sh
```

Launch a short fake-runtime smoke:

```bash
bash scripts/dev/run_fake_runtime.sh
```

Keep the debug app open:

```bash
KEEP_OPEN=1 bash scripts/dev/run_macos_app.sh
```

Run real mode from source:

```bash
export DEEPSEEK_TUI_BIN=/absolute/path/to/deepseek-tui
export DEEPSEEK_API_KEY=...
export DEEPSEEK_BASE_URL=https://your-openai-compatible-endpoint/v1
export DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_AGENT_RUNTIME=real KEEP_OPEN=1 bash scripts/dev/run_macos_app.sh
```

## Known Limitations

- Not notarized yet; Gatekeeper may require right-click `Open`.
- The app is macOS-only.
- The UI currently targets the DeepSeek-TUI Runtime API surface used by this alpha. Upstream API drift should be handled in `macos/DeepSeekAgentApp/RuntimeBridge/DeepSeekTuiRuntimeClient.swift`.
- Public release quality still needs Developer ID signing, notarization, and a hardened runtime pass.
